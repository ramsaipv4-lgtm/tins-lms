## Decision
**Problem:** Eight games (four now) must share one clock, one status machine, one story player, one scoring and persistence path
and one pack check, while a later game task (g-3 onwards) only adds a module under `packages/games/src/games/<id>/` and data.
Everything has to be testable without a browser (my unit tests carry this task) and the learner must not download any game code
before opening the arcade (AC-200). Snek (task g-1) is built in parallel and may not exist when the pack check runs.
**Options considered:**
1. One big React-only game host that owns the clock and the rules (fast to write; untestable in Node; each game would copy it).
2. A pure `Session` (no DOM) that wraps a `GameModule`, plus thin web screens that read the session. The clock, the statuses,
   the action table, scoring, scenes and the test-hook surface live in the session; the screens only draw overlays and send keys.
3. For results: the browser writes `gameResult`, cards and notes into its local PouchDB and relies on sync; or the hub writes them
   through a REST call.
4. For the Snek dependency of the pack check: import `../lang/index.ts` statically (breaks every run until g-1 merges), or
   pass Snek in (`checkPack(pack, snek)`) with a lazy loader that returns `null` when the folder does not exist.
5. For `window.__game` the spec says the server injects `<meta name="lms-test-mode">`; `main.ts` (not in my scope) only injects the
   pseudo-locale meta.
**Choice:** (2) with the DOM-free `createSession` in `packages/games/src/engine/session.ts`; (3) the hub writes (REST
`POST /api/games/results`) using one pure function `recordRound(store, input)` that works on any `{get, put, list}` store, so the
same code is unit-tested with a Map and runs in the hub; results that cannot be sent wait in a local outbox keyed so a retry is
harmless; (4) Snek is injected (`checkPack(pack, snek)`), loaded lazily by one loader (`engine/snek.ts`, also exposed to games as
`ctx.snek()` and giving the `snek` chunk of D-57); (5) a Hono middleware in `routes/testmode.ts` (registered only in test mode)
that adds the meta to HTML responses; `routes/features/games.ts` is registered from `content.ts` because `routes/index.ts` is
outside my scope.
**Why:** The spec makes the clock, statuses, actions and scoring the contract that every later row tests through `__game`; having
one session object means a fix in g-3 fixes all games. Hub-side writing gives AC-205/AC-236 (error notebook, cards, XP after
sign-out/in and in a second context) the same truth as every other screen, and `recordRound` keeps D-60 in one place (only
`mistakes[]` create cards, notes and mastery checks). The hub recomputes `teamScore` from change feeds on the person databases (new
databases are found by a one-second scan), which also covers writes from `/__test/seed`.

## What a learner will trip on
- Scene time arrives in 1/60 s slices; any "has this beat ended?" test needs a tolerance, or a 1000 ms wait never finishes.
- `rowcheck` rebuilds the web app only for `*.journey.mjs` files; a `.test.mjs` row such as AC-200 reads whatever `packages/web/dist` holds.
- `window.__game` needs the test-mode meta tag in the HTML; without it the page works but no driver can play.
- `import.meta.glob` is a Vite-only call: code that must also run in Node wraps it in `try` and falls back to a plain `import()`.
- Rolldown names chunks only if a group says so (`output.codeSplitting.groups[].name` as a function of the module id); `includeDependenciesRecursively: false` stops it pulling shared code into a game chunk.
- A `kit pattern add` copies files into `lib/` and edits `.tins/patterns.lock`, both outside a task's declared paths.

## For g-3 (and later game tasks)
- A game is `packages/games/src/games/<gameId>/index.ts` with `export default { id, actions, mount(el, ctx) }`; the folder name decides the chunk name `game-<gameId>` and the arcade tile. Until the folder exists the hub offers no tile for that game.
- Use `ctx.round` for every Skill and Knowledge event (`addSkill`, `socketCorrect(id, concept)`, `knowledgeMistake({itemId, concept, question?, given?, correct?})`, `actionMiss`, `socketAssisted`, `addGoldenCoins`, `setClaimed`, `addAssisted`, `setSocketsTotal`), then `ctx.finish(ctx.round.result('won'|'lost', ctx.clock.now()))`. The engine computes stars, score, xp and coins, writes the gameResult, cards, error notes and mastery checks, and plays `<gameId>.chapter-end` after a last-level win.
- Game actions are declared in `actions` (`ActionSpec`): keys, a button name (`act-<button>`), held actions with `releaseAction` and `releaseArg`, `keyAsArg` for strike digits, `validIn` for `calibrate`/`offset` (title and paused). `keyClashes(actions)` in `engine/actions.ts` reports two actions sharing a key in one status; call it in the game's own test.
- The game draws in `render()` (called once per frame when something moved), reads time only from `ctx.clock` (`onStep(dt)` is fixed 1/60 s of game time with assist applied; `onRaw(ms)` also runs while paused or on the title, for calibration), and takes randomness from `ctx.rng('<stream>')`.
- `ctx.lesson(cards)` opens the lesson card overlay (status `paused`, `continue` closes it); `ctx.story.play('<gameId>.escape', onEnd)` plays a scene and tells you when it ends (it returns false and never calls `onEnd` under `?story=off`); `ctx.snek()` returns the interpreter (own chunk) or null.
- Story JSON lives in `packages/games/story/universe.json` and `<gameId>.json`; the text keys must exist in `packages/web/src/strings/en.json` (`games check packages/games/story` checks it). The universe cast ids are the allowed `say.who` values.
- `mastery-skill-<concept>` rows (AC-205) are not rendered yet: `features/files/Mastery.tsx` shows `data-skill` and a "Day n" label but no such test id, and it is outside my paths.
- The team XP line on the celebration wall is added by a small DOM decorator in `features/games/index.tsx` (the wall belongs to the coach group). A cleaner fix is `coach/Wall.tsx` plus `/api/coach/wall` returning `teamXp`.
