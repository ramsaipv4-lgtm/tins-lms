## Decision
**Problem:** Five trainer/learner screens (attendance, one-tap wrap-up, absentee messages, private notes, Friday digest with lab clusters) must work from seeds, while the existing attendance routes are outside this task's files.
**Options considered:** (1) call only the existing `/api/classes/:id/attendance` and compute everything in the browser from replicated PouchDB docs; (2) add small server routes in `routes/features/attend.ts` that return exactly what each screen needs and call core (`atRisk`, `clusterSubmissions`, `waLink`, `copyAll`); (3) edit `attendance.ts`.
**Choice:** Option 2. The browser builds the `wa.me` links and the clipboard text with core; the server computes roster state, digest levels and clusters.
**Why:** Notes and lab comments must never replicate to learners, so they live in the private database and need a server route anyway. Option 3 is outside the scope paths. Option 1 would leak phone numbers and notes through class replication.
