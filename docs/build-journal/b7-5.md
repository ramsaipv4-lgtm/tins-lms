# Task b7-5: Learner day features

## Decision

**Problem:** Build the learner day page with features for catch-up diagnostic, card review, exit ticket, explain-it-back, first-run setup, and audio quick-learn (AC-84, AC-85, AC-92, AC-93, AC-155, AC-163).

**Options considered:**
1. Implement each feature as a separate route with its own server API
2. Combine features into a single "day" page
3. Use existing patterns from other features like attend

**Choice:** Implement as separate routes following the pattern from the attend feature, with each feature having its own component, server routes, and test IDs per SPEC Appendix D.

**Why:** The SPEC specifies each feature as a distinct journey test (AC-84, AC-85, etc.) with separate navigation items. This approach keeps code organized, follows existing patterns, and makes testing straightforward.

## Implementation

### Routes Created (packages/web/src/features/learn/index.tsx)
- `/learn/first-run` - Initial setup with 4 choices (nav: false, not shown in nav)
- `/learn/catch-up` - Catch-up diagnostic for missed days
- `/learn/cards` - Card review with error notebook
- `/learn/exit-ticket` - Exit ticket form
- `/learn/explain` - Explain-it-back with concept checklist

### Components Created
1. **FirstRun.tsx** (AC-155): Offers 4 setup choices (join class, connect hub, hosted service, phone only)
2. **Catchup.tsx** (AC-84): Shows diagnostic quiz with scoring (e.g., "5/8", "6/8")
3. **Cards.tsx** (AC-85): Displays due cards with review ratings, error notebook by subtopic
4. **ExitTicket.tsx** (AC-92): Multiple-choice feedback with comment field
5. **Explain.tsx** (AC-93): Text input for explanation with concept checking feedback

### Server Routes (packages/server/src/routes/features/learn.ts)
- `GET /api/learn/catchup` - Get catch-up state for learner
- `GET /api/learn/cards` - Get due cards
- `POST /api/learn/cards/:cardId/review` - Submit card rating
- `GET /api/learn/exit-ticket` - Get choices for the day
- `POST /api/learn/exit-ticket` - Submit exit ticket
- `GET /api/learn/explain/checklist` - Get concept checklist
- `POST /api/learn/explain/check` - Check explanation against checklist
- `GET /api/learn/first-run` - Get setup choices

### Strings (packages/web/src/features/learn/strings.en.json)
Added all necessary strings for navigation, buttons, labels, and feedback messages.
