# b3-1: Rotating attendance code, pairing codes, certificate ids

**SPEC rows:** AC-11, AC-12, AC-13, AC-58   **Model:** claude-sonnet-5-5   **Commits:** 31ac940 (code), rest recorded by kit close

## Decision
**Problem:** Prove presence with a code that rotates and verifies offline; pair devices with one-time codes; issue forgeable-proof certificate ids, all without reading the clock.
**Options considered:** (1) store issued codes; (2) derive HOTP-style codes from secret and period; (3) random codes. For pairing: mutate a map in place vs return new state. For certificate ids: plain hash vs HMAC.
**Choice:** HOTP over HMAC-SHA-256 (SPEC 4.5); immutable pairing state keyed by code; certificate id = first 12 Crockford base32 chars of HMAC over canonicalJson of the inputs.
**Why:** No storage, offline checks, `now` passed in (SPEC section 2), and canonicalJson from util.ts gives unambiguous input encoding.

## What a learner will trip on
- A plain object lookup of `"toString"` finds an inherited property; use `hasOwnProperty`.
- A directory argument to `node --test` does not run the files inside.
- Test period and code period must match.
- Do not apply a broad `sed` to a test file; edit the exact line.
