# b2-1: Seeded randomness

**SPEC rows:** AC-1, AC-2   **Model:** claude-haiku-4-5   **Commits:** cec40fe (base)

## Decision
**Problem:** The Core module needs a seeded random number generator that can be used for deterministic, reproducible sequences for grading, shuffling, and other functionality that requires randomness while maintaining auditability.

**Options considered:** 
1. Use a cryptographic PRNG with seeding (HMAC-SHA-256 based)
2. Implement a simple deterministic PRNG like xorshift32
3. Wrap JavaScript's Math.random (not deterministic, rejected)

**Choice:** Implemented xorshift32 algorithm with seed-based initialization. This provides:
- Fast, simple, deterministic randomness
- No async overhead (synchronous by requirement)
- Reproducible sequences from the same seed
- Proper state management for independent RNG instances

**Why:** 
- xorshift32 is a well-known, battle-tested PRNG algorithm that's simple to implement
- The synchronous requirement eliminates cryptographic hashing in the RNG loop
- Seed initialization uses simple string hashing (adequate for entropy distribution)
- `seedFor` creates stable, reproducible seeds from class and item identifiers using a simple hash function
- Fisher-Yates shuffle is a standard algorithm that uses the RNG correctly without mutation

## What a learner will trip on
- The xorshift32 algorithm requires non-zero state; the code initializes from zero-seed by defaulting to state = 1
- The range conversion `(x >>> 0) % 1000000000 / 1000000000` ensures values are in [0, 1) by using an integer division into a fixed range
- Seed hashing is intentionally simple (character code accumulation) rather than cryptographic to keep the function synchronous
- The `seedFor` function concatenates with a separator (`:`) to avoid collisions between different class/item combinations
