# b2-3: Catch-up gate and mastery map

**SPEC rows:** AC-6, AC-7, AC-8, AC-9, AC-10   **Model:** claude-haiku-4-5   **Commits:** c0f99ad

## Decision

**Problem:** Learners who miss class days need a structured way to catch up (AC-6 through AC-9), and trainers need to understand each learner's skill mastery to form study groups effectively (AC-10). The catch-up gate unlocks missed days when their diagnostic score meets the pass mark, requiring sequential unlock. The mastery map identifies skills where learners have demonstrated proficiency through recent checks.

**Options considered:**
1. For catch-up: hard-code unlock rules vs. parameterized pass mark (chose parameterized with default 6 per SPEC §4.3)
2. For mastery: time window (chose exactly 24 hours per SPEC §4.4) vs. any two checks; score threshold (chose ≥ 0.8 per SPEC §4.4)
3. Order of unlock for missed days: allow any missed day to unlock vs. strictly sequential (chose strictly sequential per SPEC rule "every earlier missed day is unlocked")

**Choice:** Implemented two functions:
- `catchUpState(input)` returns which missed days are locked/unlocked, the next locked gate day, and whether self-study is blocked
- `masteryMap(checks)` returns mastery status ('mastered' or 'not-yet') for each skill based on two most recent checks
- `gradedDueDate(gatePassedAt, extensionDays)` calculates the due date for graded work (7 days by default)

**Why:**
- Sequential unlock prevents learners from jumping ahead and missing foundational material
- The 24-hour minimum between checks for mastery ensures substantive practice, not lucky guessing
- Time-based scoring prevents a learner from losing mastery status due to a single lower score mixed into old checks
- The parameterized pass mark allows per-class customization while respecting a sensible default

## What a learner will trip on

- Thinking that passing a later missed day's diagnostic before an earlier one unlocks that later day (it doesn't; AC-7 explicitly tests this)
- Assuming a skill with a single high-scoring check is "mastered" (it's not; at least two checks 24h apart are required)
- Forgetting that `gradedDueDate` returns milliseconds (not seconds), needed for correct time comparisons
- Misunderstanding that `selfStudyBlocked` is true while *any* missed day is locked, not just the immediate `nextGate` day
