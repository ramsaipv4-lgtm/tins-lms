# b8-1: Board: trimmed Excalidraw fork, pages, Mermaid drop, PDF with ruling

**SPEC rows:** AC-97, AC-101   **Model:** claude-sonnet-5-5   **Commits:** d0d3055 (code; later commits on the same branch)

## Decision
**Problem:** The trainer needs a whiteboard on the projector (D-36) with several pages, a dropped Mermaid file that becomes shapes, and a PDF for the phones whose first page carries notebook ruling, while the canvas stays plain. The board is about 3 MB of JavaScript and must not be downloaded until the board opens (AC-101) or counted in the shell bundle (AC-102). D-7 says "hard fork vendored into packages/board", which this build deviates from.
**Options considered:**
1. Vendor the whole Excalidraw source into `packages/board` and edit it (what D-7 literally says).
2. Keep the pinned `@excalidraw/excalidraw` 0.18.1 package (already in node_modules, no new dependency allowed) and wrap it: our own page model, tabs, PDF writer and Mermaid drop, the upstream UI trimmed with `UIOptions` and CSS, everything behind the route's `load()`.
3. Paint the ruling on the canvas and export the canvas as is.
**Choice:** Option 2, a wrapper and not a vendored fork. Only the fonts are vendored (`packages/board/assets`). Pages are `board:<id>` documents in the class database; the PDF is written by our own `buildPdf`.
**Why:** The package source is not available to copy into the repo here, so option 1 cannot be built or tested; the wrapper still gives the "trimmed" behaviour (own tools, own pages, own export). The ruling must exist only in the PDF, so the PDF writer draws it, not the scene. This is a deliberate deviation from D-7 and is reported to the coordinator.

## What a learner will trip on
- Upstream's own test ids can be on invisible elements: a test that clicks them needs the element to be the hit target, or a keyboard fallback.
- `import()` of a package that is also imported statically elsewhere does not split it (the build warns `INEFFECTIVE_DYNAMIC_IMPORT` for `@excalidraw/excalidraw` in `mermaid.ts`); the real split that matters here is the route's `load()`, which keeps everything out of the shell.
- A PDF is just text: object numbers, byte offsets in the `xref` table and `startxref` must be exact; the unit test checks every offset.

## Orchestrator note: AC-101 not claimed; branch re-recorded

2.73, 2.77, 2.80, 2.80, 2.96, 3.02, 3.09 s after the builder's last changes: under 3 s on most runs,
never with margin. The remaining cost is the service worker precaching the board chunks about 2 s

the integration task b11-2. The builder's code commit had claimed AC-101 before any gate verified it,
and the gate rightly forbids removing a committed claim, so the unpushed branch was rebuilt from main
with this task's paths in one new session and the lesson's `source_refs` repointed. Lesson for the
build process: claim a row only after the gate (not a single local run) has shown it green.
