# Build Journal: b7-7 Appeals, Doubts, Drop, Accommodations, Content Improvement

## Problem
Build task b7-7 requires implementing 5 classroom features for the Coach LMS:
- AC-88: Appeal (learner appeals a score, trainer reviews)
- AC-91: Doubt queue (learners post doubts, trainer views)
- AC-152: Drop switch (trainer can drop a learner)
- AC-153: Accommodations (learner requests, admin approves, affects timers)
- AC-166: Content improvement (item analysis, misconception suggestions)

All features share the same web feature group (classroom) and use core functions already implemented in packages/core.

## Options Considered
1. Implement all features in one comprehensive pass
2. Build minimal stubs then iterate
3. Focus on one feature at a time

Chose option 1 to create the full feature group structure, with the understanding that some components may need refinement based on test feedback.

## Choice: Full Feature Group Implementation

### Architecture
- Web feature group: `packages/web/src/features/classroom/`
  - Routes for 7 screens (learn: grades, doubts, accommodations; teach: appeals, doubts, analytics; admin: accommodations)
  - Components for each screen
  - Shared strings in `strings.en.json`

- Server routes: `packages/server/src/routes/features/classroom.ts`
  - REST endpoints for all CRUD operations on appeals, doubts, drops, accommodations, item analysis
  - Uses zod for validation
  - Leverages core functions (openAppeal, appealStep, dropPlan, itemAnalysis, etc.)

### Implementation Details

1. **AC-88 Appeal**: 
   - LGrades: Lists learner's attempts with appeal button
   - TAppeals: Trainer views appeals, can uphold/reject/escalate
   - Endpoints: GET/POST /api/classes/:id/appeals, PUT to update state

2. **AC-91 Doubt Queue**:
   - LDoubts: Learners post (with anonymous option), see upvote buttons
   - TDoubts: Trainer views all doubts sorted by votes
   - Endpoints: GET /api/classes/:id/doubts, POST to create, PUT to upvote

3. **AC-152 Drop**:
   - Integration with existing roster (attend feature)
   - Server endpoints to drop/undrop learners
   - Uses dropPlan core function to determine actions (unassign tickets, remove from team)
   - Endpoints: POST /api/classes/:id/learners/:personId/drop, POST .../undrop

4. **AC-153 Accommodations**:
   - LSettings: Learner requests accommodation with time multiplier (1.0-3.0)
   - AAccommodations: Admin views pending requests, can approve
   - Server stores requests in person databases
   - effectiveLimitMs core function scales exam/shift timers
   - Endpoints: POST /api/learner/accommodations, GET /admin/accommodations, PUT to approve

5. **AC-166 Content Improvement**:
   - TAnalytics: Trainer views item analysis (p, discrimination, flags)
   - Shows misconception suggestions with accept/reject buttons
   - Endpoints: GET /api/classes/:id/item-analysis, misconceptions CRUD
