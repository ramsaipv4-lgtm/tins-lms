# b7-2: Admin: class setup, verbal syllabus, college outputs, Google opt-in

**SPEC rows:** AC-80, AC-154, AC-169 (AC-165 built but not claimed, see mistake 9)   **Model:** claude-sonnet-5-5   **Commits:** 58abe2b

## Decision
**Problem:** The admin needs screens that create a program, cohort and class, check and publish a package, draft a syllabus from typed notes, produce college reports and certificates, and switch Google features on, with no new dependency and no edit to the shell.
**Options considered:** (1) generate PDFs on the server; (2) generate PDFs and CSVs in the browser from JSON the server shapes; (3) add a PDF library.
**Choice:** Option 2: a 100-line PDF writer in `features/admin/pdf.ts`, the `qrcode` package already in the web app for the certificate QR, and server routes in `routes/features/admin.ts` that only store, read and call core (`certificateId`, `isOn`, `parsePackage`) and the Google adapter.
**Why:** D-14 forbids a new dependency, and `qrcode` is not a dependency of the server package. Reports are small. Feature switches are read through core `isOn`, so precedence stays in one place (D-22).

- Accessible names in the journeys are exact (`^...$`), so a friendly longer label fails.
- A late network answer can overwrite what the person typed on a slow phone.
- A controlled checkbox that waits for the server looks broken to an automated click.
