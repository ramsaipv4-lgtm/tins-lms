# b6-4: Sync: replication, schema check, merge pass, personal DB rules

**SPEC rows:** AC-69, AC-70, AC-71, AC-121   **Model:** claude-sonnet-5-5   **Commits:** a8ffc27, final commit by kit close

## Decision
**Problem:** /db/* is served by express-pouchdb, which knows nothing about sessions, schema versions, personal-database ownership, encrypted coach entries or conflict merging.
**Options considered:** (1) fork or patch express-pouchdb; (2) put a Hono proxy in front of /db; (3) Express-style guards on `ctx.dbGuards` that run before express-pouchdb, plus PouchDB changes feeds for the merge pass.
**Choice:** Option 3, all in `routes/sync.ts`: a schema guard (`x-lms-schema` through core `canSync`), an access guard (session, personal-database owner, org writers), a document guard (coachEntry rules) and one live changes feed per database that calls core `mergeRevisions` and writes the merged revision while deleting the other revisions.
**Why:** D-9 mounts express-pouchdb as it is; D-24 wants the merge written back by the core function, and a changes feed with `conflicts: true` sees a conflict as soon as replication lands it, well inside 5 s. Errors use the CouchDB shape `{ error, reason }` because PouchDB clients cannot parse anything else.

Other choices: update-app answers 426; plaintext or missing `enc` on a coachEntry answers 400; a minor's coachEntry answers 403 (checked first); admin may read, not write, another person's personal database; a personal or class database is created when an allowed caller first asks for it.

## Mistakes and how they were found
| # | What went wrong | Exact evidence (failing output) | How it was noticed | Fix | Proof (command + result) |
|---|---|---|---|---|---|
| 1 | Guard read the request body, so express-pouchdb found an empty stream | `error: 'stream is not readable'`, `name: 'InternalServerError'` on every write | first run of my own test, 4 of 5 failed | buffer the body, mark `req.readable`, replay the bytes as `data`/`end` events | `node --test packages/server/test/sync.test.mjs` |
| 2 | First fix still failed: `readable` was set only after raw-body had checked it | same `stream is not readable` | rerun | define `readable` as soon as the body is buffered | same command |
| 3 | Error body was `{ error: { ... } }`; PouchDB replication crashed on it | `(fatalError.name \|\| "").toLowerCase is not a function` | AC-71 test | CouchDB-shaped `{ error: 'update-app', reason }` | AC-71 test passes |
| 4 | The owner's own empty personal database answered 404 | `404 !== 200` | AC-69 test | open the database (`info()`) after the access check | 5 of 5 pass, three runs in a row |

## What a learner will trip on
- A guard that reads the request stream steals it from the next handler; it has to be played back.
- PouchDB only understands CouchDB-style error bodies.
- A conflict is a second live revision; the merge writes a new revision on the winner and tombstones the others.
