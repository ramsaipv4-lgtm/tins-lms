## Decision

**Problem:** Coach LMS v1 needs foundational crypto utilities (utf8, hex, base64, SHA-256, HMAC, HKDF, AES-GCM, canonical JSON), feature switch management, and version compatibility checking. These are core infrastructure used by every other module in the system.

**Options considered:**
1. Implement crypto helpers from scratch using Web Crypto API
2. Use platform-provided Web Crypto.subtle (async) directly in calling code
3. Create a centralized util.ts module that wraps and exposes all necessary crypto operations

**Choice:** Option 3 — centralized util.ts module with well-tested async crypto helpers exported for use throughout the core package.

**Why:** This approach provides:
- Consistent, testable crypto operations accessible to all core modules
- Clear separation of concerns (util.ts owns all byte manipulation)
- Easier to maintain and update crypto algorithms in one place
- No external dependencies (Web Crypto is built into Node 22+)
- Matches the "packages/core has zero runtime dependencies except ts-fsrs" requirement (D-3)

## What a learner will trip on

- The AES-GCM IV is always 12 bytes and is randomly generated on each call (even for the same key/plaintext). This is correct per spec, but may surprise learners expecting deterministic encryption.
- HKDF and HMAC are async operations; forgetting `await` when calling them will produce Promise objects instead of Uint8Array results.
- canonicalJson produces strictly sorted JSON with no whitespace; it looks different from JSON.stringify but is semantically identical.
- Feature switches must be predefined in switchDefaults(); unknown switch names throw an error (good for catching typos).
- Version compatibility follows the 2-version tolerance window: a client 3+ versions behind the hub must update the app entirely, not gradually.
