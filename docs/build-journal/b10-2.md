## Decision

**Problem:** Implement backup targets (S3/R2, Google Drive, USB/folder) that encrypt data before upload, and Google integrations (Meet, Calendar, Forms) with optional feature switches. Both must work against fake HTTP servers in tests.

**Options considered:**
1. For backup: implement targets as HTTP clients using fetch to fake servers
2. For folder target: use global in-memory Map vs. actual file system I/O
3. For Google: check switches before each request vs. centralized check

**Choice:**
1. All targets use fetch for consistency with network adapters
2. Folder target uses Node.js fs module to write/read files from disk
3. Google methods check their switch at the start, throwing if off
4. Key derivation uses PBKDF2 (600k iterations) followed by HKDF to derive the final encryption key

**Why:** 
- Using fetch with fake servers keeps test setup simple and the interface injectable
- Folder target needs file system I/O to pass acceptance tests that check for actual files on disk
- PBKDF2 + HKDF follows the SPEC's language about "passphrases stretched with PBKDF2" and "keys derived with HKDF"
- Per-method switch checking matches the contract ("A call whose switch is off rejects with an error naming the switch")

## What a learner will trip on

- **Folder target file I/O:** The folder target is the only one that needs file system access. New builders might try to keep all targets as HTTP clients. The acceptance tests check for actual files on disk, so proper file I/O is essential.
- **Switch checking defaults:** The spec says "a missing switch key is off". The check must be `switches[name] === true` (explicitly true), not `!== false` (which would default to true).
- **Multipart form parsing:** Google Drive multipart uploads require careful extraction of the binary data from the boundary-separated parts. Off-by-one errors in string searching will corrupt the data.
- **Binary data in HTTP tests:** When writing fake HTTP servers for tests, never concatenate binary data to strings. Use Buffer.concat() or similar to preserve byte values.
