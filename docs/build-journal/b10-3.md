## Decision

**Problem:** The Coach LMS needs to display system health status (backups, sync lag, failed checks) and run health checks (offline and online) with support for offline-only mode where online checks show last-known values.

**Options considered:**
1. Implement both functions in a single module with clear separation of concerns
2. Use async/await for all operations to handle both sync and async check functions
3. Store results with explicit `null` values when checks are skipped due to offline mode

**Choice:** Implemented two export functions (`healthDigest` and `runMorningChecklist`) in `packages/adapters/src/health.ts` with:
- Health digest that marks backups as stale if `lastSuccessAt` is null or older than 48 hours (172,800,000 ms)
- Morning checklist that runs offline checks first, then online checks (or skips them when offline)
- Online checks return `ok: null` and `ranAt: null` when offline, preserving `lastKnownAt` value

**Why:** 
- 48-hour staleness threshold matches SPEC requirement
- Offline-first execution order ensures critical health checks run even without connectivity
- Explicit `null` values for skipped online checks allow clear distinction between "not checked" and "check failed"
- Pure functions with dependency injection (via `now`, `run` callback, etc.) enable testability

## What a learner will trip on

- The distinction between "backup never succeeded" (`lastSuccessAt: null`) and "backup succeeded but is stale" is important: both make `stale: true`
- When running offline, `ranAt` is `null` for online checks, not the current timestamp
- The `lastKnownAt` field is optional in input but should be preserved (undefined if not provided) in output for online checks when offline
