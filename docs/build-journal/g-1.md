# g-1: Snek, the Python-subset interpreter (parser, two evaluators, counting, sandbox)

**SPEC rows:** AC-208, AC-209, AC-210, AC-211, AC-212, AC-213 (D-44, D-45, D-52, D-53, D-54)   **Model:** claude-sonnet-5-5   **Commits:** see `git log` on the task branch

## Decision
**Problem:** Run learner Python (a subset) in the browser and in Node with no dependencies, deterministic operation and
memory counts, hard limits that stop a run cleanly, friendly located errors, a sandbox, and a `step()` generator that
yields CPython-equal line events and pauses before each host function. It must stay fast (the bubble sort at n = 1000 is
about 9 million of our ops, run several times by the tests) and the `snek` chunk must stay under 40 KB gzip (AC-200).
**Options considered:** (1) one tree-walking evaluator written as generators for everything (simple, but every node
costs a `yield*` hop: seconds for the bubble sort); (2) a bytecode VM with an explicit frame stack (suspendable anywhere,
one semantics, but the most code and the most places for subtle bugs: handlers, comprehension scopes, callbacks from
`sorted(key=)`); (3) two evaluators on one resolved AST: a closure compiler for `run` and `callFunction`, and a
generator walker used only by `step` that handles statements and the parts of expressions that contain calls and borrows
the closures for everything else; (4) replay the program for every event (no coroutine needed, but quadratic).
**Choice:** (3). Source -> tokens (indentation aware) -> AST -> scope pass that gives every variable a frame slot
(comprehension variables get hidden slots in the enclosing frame) -> `fast.ts` closures or `gen.ts` walker. Values: int =
JS number, float = `PyFloat`, list = JS array, str = JS string, dict/set = `Map` keyed by a normalised key (so
`1 == 1.0 == True`). Counting: one op per evaluated expression node and statement, built-ins add their complexity;
`peakCells` comes from a reachability scan (strings of 2+ characters count their length, container elements count one
each) that runs when the allocation counter passes a threshold and once at the end.
**Why:** (3) gave 9.4 million ops for the n = 1000 bubble sort in about 45 ms and made `step` possible without a second
copy of the whole library (values, operators, built-ins and formatting are shared). The step walker is slow but only runs
small programs. The reachability scan is the only way to get "live" cells without reference counting every value; its
cost is bounded (it re-runs after a quarter of the live size more allocations, and a big heap is not rescanned more than
once per live/16 ops). Both evaluators agree on all 120 corpus programs, including `ops` (checked: no difference).
Differential tests against `python3` (CPython 3.14.4 is installed) drove most of the fixes below.

Choices the SPEC left open, kept for the next reader: a limit or sandbox stop (`TooManySteps`, `TooDeep`, `TooBig`,
`NotAllowed`) is never catchable by the learner's `try/except`; a host function that throws ends the run with
`RuntimeError` (same: not catchable); names like `open` are refused at compile time with `NotAllowed` only when they are
not the learner's own variable; `import os` is `NotAllowed`; unsupported syntax (`with`, `yield`, `global`, decorators)
is a `SyntaxError` that says so; `ops` on a limit stop is the first value above `maxOps` (not `maxOps` itself).
Known differences from CPython beyond the SPEC's list: no line events for comprehension iterations, for the lines of a
call spread over several lines, or for loop bodies written on the header line; `a, *b = x`, keyword-only `*`, `:=`,
`**kwargs` and user exception classes are not supported.

## What a learner will trip on
- JS arrays are the Python list, so `truthy(undefined)` must be false: a missing keyword argument is `undefined`, not `None` (mistake 1).
- `-0`: `0 * -1` is `-0` in JS and `1 / -0` is `-Infinity`; ints are normalised with `+ 0` after `*`, `%`, `//` and negation.
- Dict keys: `1`, `1.0` and `True` are one key; a tuple is keyed by a string built from its items; only the first spelling is kept.
- Method tables must have no prototype, or `x.constructor` escapes the sandbox (mistake 5).
- A limit that is thrown as a normal exception can be caught by the learner's own `except`: keep limits on a separate class.
- "Live cells" needs a reachability scan; counting allocations alone makes every temporary list look like a leak.
- `step()` events: a `for` header event comes once more when the loop ends, and a `while` header once more when the condition goes false.
