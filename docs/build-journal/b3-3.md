# b3-3: Append-only hash-chained ledger

**SPEC rows:** AC-19, AC-20, AC-21   **Model:** claude-sonnet-5-5   **Commits:** 94555fc188f43f2fb8f05f642211c26c213ed142 (code), plus the close commit

## Decision
**Problem:** Records must be correctable but any silent edit of history must be detectable (SPEC §4.9).
**Options considered:** (1) mutable rows; (2) append-only list with correction entries; (3) append-only list where every entry also stores the previous entry's hash.
**Choice:** (3), as pure async functions over an array in `packages/core/src/ledger.ts`, using `sha256` and `canonicalJson` from `./util.ts`.
**Why:** Only (3) lets `verifyLedger` name the first edited entry (AC-20) while corrections stay visible (AC-21). No clock or file I/O, per D-22.

**Pattern check (AGENTS.md rule 3):** I ran `kit patterns`. Two entries matched. `append-only-ledger` (proven) applies in idea: corrections are new entries that point at what they cancel, and `currentValue` folds to the latest. I ran `kit pattern add append-only-ledger`; its module copied `lib/ledger.mjs` and `lib/ledger.test.mjs`, but it is a file-backed money ledger (account, amount, 1-based seq, no hashes), so it does not fit the SPEC's interface and I did not use it. Those copied files sit outside my declared scope, so I deleted them (`rm -rf lib`) and re-ran the gate, which still passed. `hash-chained-log` (candidate, prose only) applies: hash = sha256 over the entry with canonical JSON, first prev is zeros. I followed it, with the SPEC's field names (`prevHash`, `hash`) and 64-zero genesis.

## What a learner will trip on
- Hashing `undefined` optional fields: add `reason` and `corrects` to the body only when present.
- Hashing without `prevHash` would not link entries.
- A hash chain does not detect deletion of the last entry; the newest hash needs an outside anchor.
