# b7-1: Web foundation

**SPEC rows:** AC-81   **Model:** claude-sonnet-5-5   **Commits:** 9c21b82

## Decision
**Problem:** Eight later tasks add screens to one app in parallel; the shell must not need edits from them.
**Options considered:** (1) one router file everyone edits; (2) registry discovering feature folders by `import.meta.glob`; (3) one app per group.
**Choice:** Option 2, a tiny History-API router, session context, strings system with pseudo-locale, PouchDB helpers loaded lazily, vite-plugin-pwa.
**Why:** No merge conflicts, no new dependency (D-14), one installable offline app (D-5). Shell JS is about 51 KB gzip.

## What a learner will trip on
- Test ids named by role (`home-learner`), not by URL space.
- Pseudo-locale must be on at build time or by a `<meta>`; the server does not send it.
- A used join code gives 409 `{error:{code:'used'}}`; show a readable message.

## SPEC gaps and server needs
- G-A: nothing exposes LMS_PSEUDO_LOCALE to the web. Server could inject `<meta name="lms-pseudo-locale" content="1">` into index.html (the web reads it), or the web build reads `LMS_PSEUDO_LOCALE=1` (done).
- G-B: no passkey/Google sign-in or sign-out routes in Appendix A; the sign-in screen calls `POST /api/signin/passkey|google` and shows "unavailable"; sign-out calls `POST /api/signout` (ignored on failure). Passkey creation during join is not implemented.
- G-C: join requires name and rollNumber on the server while Appendix D calls them optional; the web falls back to "Learner" and `roll-<code>`.
