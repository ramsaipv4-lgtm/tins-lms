# b7-8: Coach space, screenshot import, portfolio, engagement

**SPEC rows:** AC-156, AC-162, AC-168 green; AC-94 not claimed   **Model:** claude-sonnet-5-5   **Commits:** 691c2077d12443afe8315f07dbd5a9460ce12b54

## Decision
**Problem:** The Coach space must be private (its own PIN, encrypted data), run the 5-stage coaching conversation in at most 25 taps, read a diet screenshot on the phone with OCR, build a portfolio site, and host the engagement features (Heading Strike, team wall, story mode) without touching the shell.
**Options considered:** (1) Put coach data in PouchDB through `app/db.ts`; (2) talk to the hub's `/db/person-<key>` CouchDB endpoint with `fetch`; (3) keep Coach data on the server. For OCR: bundle the tesseract worker and core with Vite, or serve them from the hub.
**Choice:** Option 2: a random data key wrapped by a PBKDF2(PIN) key lives in `coachMeta:main`; every plan version and tracker entry is a `coachEntry` document holding only `enc`. OCR worker, core and English data are served by `/api/coach/ocr/*` on the hub and `tesseract.js` is imported on first use only.
**Why:** `app/db.ts` could not load in the browser bundle (see mistake 1) and the shell is not mine to change. The hub already refuses plaintext coach entries, so the encryption stays on the device. Serving OCR files from the hub keeps the 300 KB shell budget and avoids any CDN (D-11).

## What a learner will trip on
- Nav names in the journeys are anchored regexes: "Food", not "Food and screenshot import".
- `getByLabel` also matches `aria-labelledby` on containers.
- OCR needs the English data file on the hub (`LMS_TESSDATA_DIR` or `<data dir>/tessdata/eng.traineddata.gz`).
