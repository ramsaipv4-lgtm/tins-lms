# b11-2: Web shell integration, accessibility and strings

**SPEC rows:** AC-99, AC-123, AC-165, AC-101 green; AC-153 not claimed (Shift is not merged: the journey now gets past the nav and request steps and stops at `no visible link/button/tab named /^(shift|the shift)$/i`)   **Model:** claude-sonnet-5-5   **Commits:** cf4afc5

## Decision
**Problem:** Nine groups were built in parallel and each passes alone. Merged, the shell needs hooks the groups worked around: a database library that does not bundle, per-role homes, switch-gated nav, a kiosk flag, a way to catch nav-name collisions, a service worker that blocks the board's 3 s budget, and a gate that hides journey errors.
**Options considered:** (1) fix each workaround inside its group; (2) give the shell a hook per concern (registry fields `home`, `switch`, `link`, a kiosk module, a pure `nav.ts`) and delete the workarounds; (3) leave collisions to be found by journeys. For AC-101: reorder workbox's generated precache; or write the worker (`src/sw.ts`) with two caches.
**Choice:** option 2 for the hooks, a script (`scripts/navcheck.mjs`) in the gate for collisions, and an own service worker: core cache in parallel at install, board chunks warmed in the background for staff only.
**Why:** workbox's `install` fetches precache entries one at a time (`for ... await`), and the worker controls no page until install finishes, so ordering could not make the page controlled earlier. A small core makes control arrive about 60 ms after the shell is ready.

## What a learner will trip on
- Two nav entries whose names share a word: the journey takes the first match. Order is the only lever besides renaming.
- A service worker controls no page until its install finishes; precache size is time to control.
- Static compression above a size threshold changes what code that edits the HTML sees.
