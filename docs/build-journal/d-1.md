# d-1: Product demo videos (`node demos/run.mjs`)

**SPEC rows:** none (a tool for showing the product; it reads SPEC §4 to §7 for its coverage table)   **Model:** claude-sonnet-5-5   **Commits:** see `git log` for this task's session

## Decision
**Problem:** The owner wants product-demo videos of the real app: a runner that starts a hub, fills it with believable activity, records walkthroughs with Playwright, converts them to mp4 and says which SPEC feature shows where. A previous builder wrote `demos/run.mjs`, `demos/lib/*`, nine scene files and a seed folder, none of it ever run (the container restarted before the first recording).
**Options considered:** (1) throw the first draft away and start again; (2) run it, fix what breaks and add the missing videos and the coverage table; (3) record by driving the app through its HTTP API and screenshots instead of a browser. For the coverage table: (a) a hand-written list with times typed in; (b) a list that names scenes, with times read from each recording's own scene log. For long runtime: cut videos, or shorten pauses.
**Choice:** Option 2 (option 3 was never tried): the existing structure (one hub per video, `stage` helper with cursor, caption bar and pacing, scene files that fail without hiding it) was sound. Coverage list (b): `demos/lib/coverage.mjs` names `video + scene title`, and `index.md` looks up the time in `out/<name>.json`; a scene that is missing or failed is printed as UNVERIFIED instead of trusted. Runtime was brought under 20 minutes by scaling pauses (`normal` pace = 0.35 of the original pause lengths) while caption reading time was kept readable.
**Why:** A table with typed-in times goes stale the first time a scene is edited; this one cannot. The first draft had only been written, not run, so the first real task was to run it and look at the frames.

## What was built
- `demos/run.mjs`: options `--only`, `--headed`, `--pace slow|normal|fast`; writes `out/<name>.mp4/.webm/.json` and `out/index.md`. `fast` is a developer mode (no video).

- `demos/README.md`, a "Product demo videos" section in `README.md`, `demos/.gitignore` (`out/`).

## What a person adding a video will trip on
- Captions are shown first, then the action, so the screen under a caption is still the previous state for a moment. Do any scroll or navigation before the scene if the caption is about what the screen already shows.
- `s.go('Name')` finds the first nav link with that exact name; some names occur twice (G). Use a URL with `signInAs(person, path)` when it matters.
- Scene titles in `coverage.mjs` must equal the `s.scene(...)` titles; a mismatch prints UNVERIFIED in `index.md`.
- Seeds are additive. Every demo seeds `base`, `demo-extra`, `demo-att-d0` unless it says otherwise.
