## Decision

**Problem:** Implement four core functions for Coach LMS v1: forming study groups with skill diversity, running estimation poker rounds, parsing standup blockers, and checking explained concepts against a checklist.

**Options considered:** 
- For study groups: use existing RNG from rng.ts (if available) vs. implement deterministic hashing. Since rng.ts is out of scope, implemented a deterministic hash-based RNG.
- For poker consensus: interpret "neighboring cards" as position in Fibonacci sequence [1,2,3,5,8,13] vs. numerical distance. Testing revealed position-based is correct.
- For standup blocking: use simple substring matching vs. whole-word regex matching. SPEC requires partial words not to match, so used regex word boundaries.
- For explanation checking: case-sensitive vs. case-insensitive matching. SPEC requires case-insensitive with punctuation ignored.

**Choice:** 
1. **formGroups**: Shuffle people deterministically, partition into groups of near-equal size, improve diversity by attempting swaps
2. **pokerRound**: Check if lowest/highest vote positions in ALLOWED_CARDS list differ by ≤1 for consensus; return most common (ties→higher)
3. **parseStandup**: Check for blocker keywords (blocked, stuck, waiting on/for, can't, cannot, need help) with whole-word regex matching; negations override (none, no blockers, not blocked, nothing)
4. **checkExplanation**: Normalize transcript (lowercase, remove punctuation), check each concept/misconception phrase using whole-word regex matching

**Why:** 
- Position-based poker consensus matches the SPEC examples (3-5 and 8-13 are both consensus despite different numerical gaps)
- Whole-word regex avoids false positives ("cached" ≠ "cache", "unblocked" ≠ "blocked", "dnssec" ≠ "dns")
- Deterministic grouping enables testing and reproducibility; seeded random shuffle provides good distribution
- Skill diversity improves group learning outcomes per the SPEC requirement

## What a learner will trip on

- **Fibonacci "neighboring"**: The [1,2,3,5,8,13] allowed cards are a Fibonacci sequence. "Neighboring cards" for consensus means adjacent *positions* in this sequence (3-5 are neighbors, 5-8 are neighbors, but 3-8 are not), not by numerical distance. The gap itself increases (1→2 is +1, but 8→13 is +5).
- **Word boundaries in regex**: Use `\b` word boundaries to prevent partial-word matches. `\bblocked\b` won't match "unblocked" or "blocked-on" (if hyphenated), but will match "Blocked" (case-insensitive). Test edge cases like "resolvers" vs "resolver", "cached" vs "cache".
- **Group partition with remainder**: When distributing n people into groups with baseSize each, remainder groups should get baseSize+1, not the other way around. For 7 into 3 groups: baseSize=2, remainder=1 → sizes [3, 2, 2].
- **Concept matching as whole phrases**: The `anyOf` field can list multi-word phrases like "virtual memory". The match must find the entire phrase as consecutive words with spaces (punctuation removed). "virtual-memory" matches (punctuation ignored) but "memory virtual" does not.
