# g-0: per-row feedback tool (rowcheck) and the nine games switch keys

**SPEC rows:** D-66 (new), D-49 and AC-49 (kept green; table already in SPEC)   **Model:** claude-sonnet-5-5   **Commits:** see `git log` on the task branch

## Decision
**Problem:** The acceptance suite is hidden from builders (D-40). The gate runs the whole suite (30 to 55 minutes) and
prints failures only for claimed rows, so a builder of one game has no cheap way to ask "does my part of AC-207 pass?".
A filter that selects nothing must also never look like a pass.
**Options considered:** (1) tell builders to call `node --test --test-name-pattern=... acceptance/...` themselves: they
would have to know the check file (reading the suite) and a typo in the pattern prints a green run with zero tests;
(2) add a "rows" argument to `scripts/gate.mjs`: it would change the thing the orchestrator trusts as the proof, and the
gate does not know parts; (3) a separate small script that reads SPEC.md the way the gate does, filters by test-name
prefix, and fails on zero matches.
**Choice:** (3), `scripts/rowcheck.mjs`, recorded as SPEC D-66 before the code. It takes `--root`/`ROWCHECK_ROOT` so its
unit tests run on a fixture repo and not on the real suite.
**Why:** It reuses the gate's own row regex and child-environment rules (so it agrees with the gate about which file a
row means), leaves the gate untouched, gives the same failure detail as the gate minus stack lines into `acceptance/`
(a builder must not learn test paths or line numbers), and turns "matched nothing" into exit 1 with a message.
The exit-code contract follows the `pure-core-cli-contract` pattern (0 ok, 1 domain failure, 2 usage error); no pattern module was
copied because rowcheck does no money, history or user-file writing (its one write is a scratch TAP file under `.tins/`).

The nine games keys (`games`, `game.syntaxDrop`, ... `game.garage`, all on) were added to `switchDefaults()`; D-49 and
AC-49 in SPEC.md already list them, so no SPEC row changed for that part.

## What a learner will trip on
- A test-name filter that matches nothing makes `node --test` exit 0. That is why rowcheck counts matches itself.
- `node --test` prints a parent test's line after its children's; the tool has to build the tree from indentation.
- A skipped test is `ok ... # SKIP` in TAP: easy to count as a pass.
- In the gate's regex a Check cell with several files must not wrap each one in backticks.
- `--test-name-pattern` is a regular expression: `AC-5` also matches `AC-55`, so rowcheck anchors it (`^AC-5(?![0-9])`) and escapes `--part`.
