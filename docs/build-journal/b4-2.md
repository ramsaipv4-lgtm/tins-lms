**SPEC rows:** AC-22, AC-23, AC-24   **Model:** claude-sonnet-5-5   **Commits:** 8047257 (code), rest recorded by kit close

## Decision
**Problem:** Run a timed "shift" of tickets with SLAs, seeded variants and a rubric, as pure functions with no clock and no Math.random.
**Options considered:** (1) list only arrived tickets in state, as the first SPEC text said; (2) list every ticket from the start with its seeded variant and let `slaReport` filter by arrival. For randomness: use rng.ts (still an empty stub, not on main) or a private generator.
**Choice:** Option 2 (SPEC 4.10 was corrected by the orchestrator to say so). A private xmur3 + mulberry32 generator, one value consumed per pack ticket in pack order. rng.ts was empty in this worktree, so `createRng`/`seedFor` were not used. Wrong answer leaves the ticket open; resolve without an answer is accepted; late resolve is `breached` and scores 0.
**Why:** Variants must be fixed by the seed at start; arrival only matters for SLA reporting. Keeping progress per ticket makes status a pure function of (progress, elapsed).

## What a learner will trip on
- A spec sentence ("only arrived tickets are listed") can contradict the acceptance check; changing the hash will never fix that. Stop and ask rather than guess.
- Commands that read stdin (`cat > file` with no input) hang.
- Wrong answer vs no answer: no answer is treated as accepted.
