# c-2: course citations point at commits on main (RF-33)

**SPEC rows:** D-41 (new; no AC rows)   **Model:** Claude Sonnet 5.5   **Commits:** see `git log task/c-2`

## Decision
**Problem:** `kit close` adds `Session:` trailers by rewriting the session's commits, so their
hashes change. BUILDER.md step 6 told builders to commit code, take `git rev-parse HEAD` and cite
that sha in `source_refs` and code fences before close. So 36 of the 42 course steps cite shas that
exist only as dangling objects on the machine that made them. On a fresh clone
`node skill-template/checks/check.mjs course --repo .` fails with 70 "check 13: ... cannot read
<path>@<sha>" errors and the whole gate fails (AC-143 cannot hold).
**Options considered:** (1) tell builders to cite the post-close sha: impossible, the sha does not
exist until close, and the lesson is inside the commit being closed. (2) Make the check accept
dangling shas (skip when the object is missing): the check would then prove nothing on a fresh
clone; rejected. (3) Keep the builder's pre-close sha so the check passes while the builder works,
and have the orchestrator re-point each cited sha to the post-close commit with the identical tree
after close, then check in a fresh clone before merging. (4) Re-point the existing course once,
from a map of old sha -> commit on main with the same tree.
**Choice:** Options 3 and 4. SPEC D-41 states the rule (citations name commits reachable from main,
the commit as it exists after close; the course check passes on a fresh clone). BUILDER.md step 6
now describes the re-pointing hand-off. The 36 existing lesson files get their sha strings replaced
from the owner-supplied patch/map.
**Why:** Trees are byte-identical between a pre-close commit and its post-close rewrite, so every
excerpt still matches and no excerpt, prose or citation path has to change. A fresh clone is the only
place that shows whether a cited sha is really in history.

## What a learner will trip on
- A sha taken with `git rev-parse HEAD` before `kit close` is not the sha that ends up in history.
- `git cat-file`/`git show` on such a sha works on the author's machine (dangling object) and fails
  on every other clone, so only a fresh clone (`git clone --no-local`) tells the truth.
- Six steps already cite shas that are on main unchanged (map lines where old = new); not every
  citation needs replacing.
