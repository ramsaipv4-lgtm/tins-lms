# b6-8: Sign-out, passkeys, Google sign-in stub, optional join fields, pseudo-locale meta

**SPEC rows:** AC-81, AC-62   **Model:** claude-sonnet-5-5   **Commits:** 7693c1a, final commit by kit close

## Decision
**Problem:** Learners need to sign out and sign back in without passwords or SMS; join must work without name and roll number; the server must announce the pseudo-locale in index.html.
**Options considered:** (1) long-lived cookie only; (2) one-time codes by SMS/email; (3) WebAuthn passkeys with attestation none and ES256, verified with Web Crypto and a minimal CBOR reader.
**Choice:** Option 3 inside `packages/server/src/routes/accounts.ts`. Challenges are held in server memory (one-time, 5 minutes on `ctx.clock`), public keys as JWK in the private database (`passkey:<id>`). Sign-in routes are mounted from `main.ts` on a small separate Hono app, and the same fetch wrapper injects the pseudo-locale meta.
**Why:** no secret is stored (D-28), no dependency is added (D-26), and the scope paths allow only accounts.ts and main.ts. The central guard in `core/guard.ts` (out of scope) lists `/api/sign-in`, not `/api/signin`, so the sign-in routes would answer 401 on the main app; the separate mount avoids editing it. Google sign-in checks the ID token with Google's tokeninfo endpoint when `LMS_GOOGLE_CLIENT_ID` is set and needs a linked `google:<sub>` record; otherwise 501 `not-configured`.

## What a learner will trip on
- The session gate list says `/api/sign-in`, SPEC says `/api/signin`: a public route under the wrong prefix answers 401.
- Web Crypto verifies raw r||s; authenticators send DER.
- A built `index.html` can contain the pseudo-locale string in a comment.
- A SPEC change (optional name) makes older tests stale: change the test with the SPEC.
