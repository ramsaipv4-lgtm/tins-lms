## Decision
**Problem:** Implement six data processing modules for the Coach LMS that analyze screenshots, group similar questions, assess learner risk, analyze test items, cluster mistake patterns, and reflow lesson plans.

**Options considered:** 
- Implement all modules with comprehensive error handling from the start
- Start with simple implementations and refine based on test feedback

**Choice:** Started with straightforward implementations and refined based on test feedback.

**Why:** Test-driven development allows for rapid iteration and ensures all implementations meet the actual acceptance test requirements rather than assumptions about them.

## What a learner will trip on
- The difference between `same-line-number` and `next-line-number` in screenshot rules requires careful attention to which line the OCR anchor matches on
- Jaccard similarity threshold of 0.6 for FAQ grouping means stop words should be removed before calculating similarity, which affects what "similar" means
- Reflow logic needs to consider all days up to `throughDay`, not just uncovered topics - must track both the source day and the new location
- Item analysis discrimination calculation requires proper grouping of learners by total score rank, with careful handling of the 27% cutoff
