## Decision
**Problem:** Provision learners on GitHub and Forgejo, let persona bots open PRs but not merge, and block pushes containing credentials, with no real service in tests.
**Options considered:** (1) vendor SDKs mocked in tests; (2) plain `fetch` with injected base URLs tested against `node:http` fakes; (3) real throwaway accounts.
**Choice:** Option 2, reusing the tins-kit scanner (`.tins/kit/src/secrets.mjs`) for the push check.
**Why:** D-14 forbids new dependencies, a fake server is a drop-in for an injected URL, and real accounts risk leaking tokens (D-28).

## What a learner will trip on
- `node --test` wants files or a glob, not a directory.
- Provisioning throws on any failed step, but merge/write/token report `{ ok: false }`; mixing these up breaks callers.
- Forgejo needs a team id in the URL, so the adapter looks the team up by name first.
- Writing a secret-shaped literal in a test trips the repo's own scan; build it from pieces.
