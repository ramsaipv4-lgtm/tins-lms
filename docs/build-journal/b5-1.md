# b5-1: Package import and content gate

**SPEC rows:** AC-51, AC-52, AC-53, AC-54   **Model:** claude-sonnet-5-5   **Commits:** 0d69d2fe3e0bb1525f66b2624049bedb6679e7a6

## Decision
**Problem:** Import a course package given as a map of path to text, accept the v1.1 and v1.2 layouts, and run checks G1 to G8 with expiring waivers (G7 never waivable).
**Options considered:** (1) walk real folders; (2) one parser per layout; (3) one day-finder that maps both layouts onto one key, then pure checks over the map.
**Choice:** Option 3 in `packages/core/src/gate.ts`, reusing `parseScriptSections` and `scriptTotalSec` from `pace.ts`.
**Why:** The map form needs no file system and SPEC fixes the signature. One key means both layouts give identical days.

## What a learner will trip on
- SPEC does not say how a day is keyed across layouts; the failing count was the only clue.
- Waiver cap is relative to the `now` argument, so tests need a fixed `now`.
- Whether a waived check keeps `pass: false` is not stated; I kept `pass: false, waived: true`.
