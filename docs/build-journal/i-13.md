# i-13: unit tests fall back to Playwright's default Chromium; ignore .lms-data/

**SPEC rows:** none (integration fix)   **Model:** claude-sonnet-5-5   **Commits:** see the session commit

## Decision
**Problem:** tele.test.mjs, board.test.mjs and foundation.test.mjs read `process.env.PLAYWRIGHT_BROWSERS_PATH ?? '/opt/pw-browsers'` with `readdirSync`; on a machine without that folder, 7 unit tests crash. Also `.lms-data/` (default data folder) was not git-ignored.
**Options considered:** (a) one shared helper (cannot live in a new file outside the scope paths); (b) try/catch around `readdirSync` only; (c) check `existsSync`, drop the variable before Playwright is imported, then plain `chromium.launch()`, as three small identical blocks.
**Choice:** (c), plus a test in foundation.test.mjs and `.lms-data/` in .gitignore.
**Why:** (b) is not enough because Playwright caches the variable when it is imported (see mistake 1); (a) is not possible in scope, and three five-line blocks are simpler than a new dependency between test files.

## Mistakes and how they were found
| # | What went wrong | Exact evidence (failing output) | How it was noticed | Fix | Proof (command + result) |
|---|---|---|---|---|---|
| 1 | My plan assumed skipping `readdirSync` was enough. Playwright caches the browsers folder at import, so a bare `launch()` still looked in the missing folder. | `browserType.launch: Executable doesn't exist at /nonexistent/path/chromium_headless_shell-1243/chrome-headless-shell-linux64/chrome-headless-shell` (AC-81 tests that ran after my new test, with the variable already restored) | first run of the new test before the fix: besides its own `ENOENT: no such file or directory, scandir '/nonexistent/path'`, two later tests failed this way, so the import had cached the bad path | `delete process.env.PLAYWRIGHT_BROWSERS_PATH` before the import when the folder is missing | `PLAYWRIGHT_BROWSERS_PATH=/nonexistent/path node --test` on the three files: 17 pass, 0 fail |

Other runs: the pre-fix run with the original files and a missing folder (7 failed, 9 passed of 16) was the intended reproduction, not a mistake.

## What a learner will trip on
- On this machine `/opt/pw-browsers` exists but is empty, so the old code did not crash here; only a missing folder reproduces it.
- Environment variables read at import time must be set or removed before `import()`, and ES modules are cached for the whole process.
