## Decision
**Problem:** Six later server tasks need the same ground: a running server with /db and Hono side by side, sessions, role guard, validation and test mode.
**Options considered:** (1) each route module builds its own access; (2) one shared `ctx` plus placeholder modules with one `register(app, ctx)` signature; (3) a decorator framework.
**Choice:** Option 2. `core/ctx.ts` builds store, clock, sessions, guards; `routes/index.ts` registers all modules and documents `ctx`.
**Why:** later builders edit only their own module and cannot drift on cookies, roles or error shape; decorators are not allowed (D-1).

Other choices: sessions are in memory (token to person and roles); join codes and the admin invite are stored only as SHA-256 hashes in a private database that /db refuses to serve; a repeated roll number returns 200 with `already-enrolled` and consumes the code (SPEC is ambiguous on status); `/__test/clock` freezes the clock.
