# b4-3: Appeals and AI policy

**SPEC rows:** AC-25, AC-26, AC-27   **Model:** claude-haiku-4-5   **Commits:** (see git log)

## Decision

**Problem:** 
The Coach LMS system needs to support learner appeals of graded work and enforce AI policy restrictions during assessments. AC-25 and AC-26 specify the appeals workflow (open → upheld/rejected → escalated → final-upheld/final-rejected), with automatic escalation after 7 days of inaction. AC-27 specifies AI tool access policies (off, allowed, explain-only) and usage tracking.

**Options considered:**
1. Model appeals as a simple state machine with automatic escalation on read
2. Model appeals as a state machine with explicit escalation triggered by `appealTick`
3. Implement AI policy as dynamic lookup or static rules

**Choice:**
- Chose option 2: `appealTick` is responsible for automatic escalation, allowing tests to control time without side effects
- Chose option 3: static rules in `aiAllowed` and simple summary generation in `aiUsageSummary`

**Why:**
- Explicit escalation via `appealTick` follows the pattern of other SPEC modules (pairing, release) where time-based state changes are explicit
- Static rules are simpler to test and reason about; they match the SPEC's straightforward policy definitions

## Mistakes and how they were found

No gate failures were encountered. The implementation passed all acceptance tests on first run. The test suite (AC-25, AC-26, AC-27) validated:
- Appeal window enforcement (7 days)
- Unread confirmation handling (opens as upheld with reason)
- Automatic escalation after 7 days via `appealTick`
- Final state immutability
- History chain building
- AI policy enforcement (off, allowed, explain-only)
- Usage summary formatting

## What a learner will trip on

1. The 7-day appeal window is exactly 7 × 24 × 60 × 60 × 1000 milliseconds, not "approximately" 7 days. Edge cases at the boundary are important.
2. `appealTick` returns a new appeal object; the caller must replace the old one. Forgetting this means escalations don't persist.
3. AI policy is checked per tool kind, not globally. "Explain-only" allows only `chat`, not `repo-write` or `run-command`.
4. Final decisions (states `final-upheld` and `final-rejected`) are immutable. Further calls to `appealStep` on a final appeal return the appeal unchanged.
