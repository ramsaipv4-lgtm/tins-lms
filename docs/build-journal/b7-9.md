# b7-9: Offline phone profile, file exchange, export my data, robustness

**SPEC rows:** AC-95, AC-96, AC-98, AC-167   **Model:** claude-sonnet-5-5   **Commits:** c4117568b905055221763675551bc228d8055749

## Decision
**Problem:** After its first load a phone must keep working with the hub off (content, cards, diagnostic, mastery map) and sync on reconnect; classes with no hub link need signed file exchange; learners need their own data export; the hub going down needs a rehearsal, a kiosk mode and a data meter.
**Options considered:**
1. Replay cached API answers from the service worker. 2. Keep a hub bundle in IndexedDB plus a local personal PouchDB that replicates, computing with core on the device. 3. A home-made sync protocol.
**Choice:** Option 2, with the screens in the shell chunk and the bundle fetched as soon as the person is known.
**Why:** Cached answers cannot record reviews or results; a home-made protocol would redo CouchDB revisions; core already runs in the browser (D-22).

## What a learner will trip on
- Anchored accessible names: a label must be exactly the word the journey looks for.
- A bundled library that imports a Node built-in fails only in the browser build.
- Going offline immediately after load exposes anything still loaded lazily.
