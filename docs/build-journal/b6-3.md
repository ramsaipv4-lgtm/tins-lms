# b6-3: Packages, gate on upload, sealed sections and teleprompter release

**SPEC rows:** AC-67, AC-68   **Model:** claude-sonnet-5-5   **Commits:** 9983740

## Decision
**Problem:** Trainers upload a course package as a tar and the hub must run the content gate before it can be published. Learners must receive each day's sections sealed, and the key for a section must only be handed out when the teleprompter reaches it, when "release all" is tapped, or (ungraded sections only) when its planned time arrives. Seeded `day` docs carry a plaintext `body` that must never be stored, served or replicated.
**Options considered:** (a) seal at read time from a plaintext kept in the private db; (b) seal when the day doc is written, keep only ciphertext in the class db and the day key in the private db; (c) edit the seed route to strip bodies.
**Choice:** (b), done by wrapping `ctx.store.put` inside `content.ts`, so every write of a `day` doc into a `class-*` database (seed, publish) is sealed on the way in.
**Why:** The seed route is outside this task's paths, and a wrapper covers every writer with one rule. The class database then holds only ciphertext, so replication cannot leak plaintext. Release decisions stay in core (`releasePlan`, `isReleased`), and the route only supplies the clock and the reached ids.

## What a learner will trip on
- A gate failure message that is only `expected: true actual: false` says nothing about the cause. Observe your own program (log requests, compare sizes) before guessing at fixes.
- A green own-test does not prove the hidden test sends the same bytes.
- Sealing must happen at write time. Sealing at read time leaves plaintext in the replicated database.
- Graded sections never release by time: `isReleased` handles that, do not re-implement it in the route.
